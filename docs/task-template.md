# 派工模板與例外分流

開發者派工給 coding agent 時用的格式。不必每格都填，但「驗收」與「例外」缺了，agent 就得自己決定什麼叫做完、遇到問題要不要停。

## 模板

```text
目標：玩家會看到什麼改變（一句話）
不做：明確排除的範圍
AI 負責：需要判斷或查證的部分（找證據、比對外部專案、取捨、寫程式與測試、三語文案）
程式／規則負責：既有或要新寫的確定性部分（求解器、產生器、測試、硬約束）
證據：samples 路徑／外部專案檔案路徑／wikiwiki 條目
驗收：自動＝哪些測試；人工＝誰看什麼（三語截圖、live 步驟）
例外：遇到 X 就停／遇到 Y 記下繼續（未寫的依下方分流表）
可否 commit：依 AGENTS.md 的條件，或「先不 commit」
```

## 分工判準

- 照同一份說明做，兩人答案必須一樣 → 程式或固定規則；容許不同、要比好壞 → AI。
- AI 的產出必須能被自動發現錯誤；不能時，縮小 AI 的範圍或在驗收寫明人工檢查。
- 能把一次性判斷寫成產生器、測試或查表的，優先寫成程式，不每次重新判斷。

## 檢查位置

| 步驟 | 檢查 | 由誰 |
|---|---|---|
| 動手前 | 證據在不在、規格是否衝突 | agent 列出，缺證據依分流表 |
| 每次改動後 | 型別檢查、相關 Vitest | 程式 |
| commit 前 | `npm run check`（型別＋全部測試＋正式 build），pre-commit hook 自動執行 | 程式 |
| commit 前（介面） | 三語排版、真實視窗尺寸預覽 | 開發者看預覽 |
| 上線後 | live 行為 | 開發者，agent 提供手動步驟 |

agent 不得用 `git commit --no-verify` 略過 hook；確實需要略過時先問開發者。

## 例外分流

| 例外 | 處理 |
|---|---|
| 測試或型別錯誤 | agent 自行修；同一錯誤試 3 次仍失敗就停下回報 |
| 缺證據（欄位、edge、新裝備值） | 先依 AGENTS.md 硬約束 8 查外部專案原始碼；仍查不到才保留原始值或 `null`，登記待驗證並寫明查過哪些來源，其他部分繼續 |
| 文件與程式不一致 | 以程式與測試為準，回報差異，不停 |
| 介面或版面判斷 | 先給預覽，不 commit |
| 動資料格式、DB、備份 | 先停，說明相容或遷移做法，等開發者同意 |
| 需要 live 驗證、push、release | 停，交開發者 |
| 403／429、帳號被標記 | 立刻停，不重試 |

## 例外的歸宿

同一種例外或 agent 錯誤出現第二次，就依序找歸宿：能寫成測試或程式檢查的先寫；寫不成的寫進 `AGENTS.md` 或對應規則檔；確定只能靠人判斷的，寫進該功能的人工驗收步驟。過時的規則一併刪除。
