Fleet Chronometer — 重建指南

MV3 瀏覽器擴充：被動觀察《艦隊これくしょん -艦これ-》自身的 kcsapi 流量， 於本機重建遊戲狀態、預測戰鬥、歸檔歷史。純前端、無後端、不上傳。 本文件是特殊情況下重建專案的備案：先說明如何保住與還原原始碼，再給出不常變動的架構骨架與重建順序。

00本文件的定位

  • 寫的是：長期穩定的架構、資料流方向、重建順序與最容易做錯的事。
  • 不寫的是：欄位、公式、各功能行為與 UI 規格。這些會隨功能改動，抄一份必然過時； 本文件只指出它們的所在位置（§8）。
權威順序

衝突時依序為準： ① 原始碼 → ② tests/ → ③ AGENTS.md → ④ docs/engineering/ → ⑤ 本文件。

本文件提到的版本號由 tests/structure-doc.test.ts 對照程式碼， 升版而未更新本文件時測試會失敗（§9）。

01備份與還原原始碼

最可靠的重建來源是原始碼本身：完整 git 歷史、測試（可執行的規格）與 samples/ 的真實封包。 這三者都在版本庫裡，所以備案的重點是讓版本庫有一份與 GitHub 無關的副本。

建立備份

npm run backup:repo -- <備份資料夾>
  • 產出 fleet-chronometer-YYYYMMDD-HHMMSS.bundle：所有分支與 tag 的完整歷史，單一檔案， 建立後自動驗證。
  • 備份資料夾必須在專案以外，例如雲端同步資料夾或外接碟；放在專案內會被拒絕。
  • 只含已 commit 的內容，有未 commit 的變更時會提示。.gitignore 的抓取快取 （tools/*/.cache）不在備份內，需要時由各產生器重新抓取。
  • 建議每次發版或大改後做一份，保留最近幾份即可。

從備份還原

git clone fleet-chronometer-YYYYMMDD-HHMMSS.bundle fleet-chronometer
cd fleet-chronometer
git remote set-url origin <新的遠端>   # 需要時
npm install                             # postinstall 會執行 wxt prepare
npx tsc --noEmit && npm test && npm run build

型別檢查、測試與 build 都通過，就代表還原完整。使用者的遊戲資料不在版本庫裡，而是由擴充本身的 備份功能（情報總括「資料備份與還原」）保存，見 docs/engineering/backup.md。

02產品與硬約束

一句話：觀察遊戲自身的 kcsapi 回應 → 於本機 reduce 成遊戲狀態 → 面板即時顯示艦隊、遠征、入渠、基地航空隊、關卡進度與戰鬥預測 → 歷史歸檔成可查詢、可備份的本機資料庫。

硬約束的完整條文在 AGENTS.md。重建時影響架構形狀的是這五條：

約束對架構的影響
被動觀察 只掛遊戲 window.axios 的 response interceptor，原樣回傳；不取代 fetch／ XMLHttpRequest，不重放、修改、延遲或代發請求。
憑證不落地 api_token／api_verno 在入列前、bridge、background 三處移除，永不寫入 DB 或送出。
擷取與 UI 解耦 資料由 service worker 寫入 IndexedDB 事件日誌；面板只是訂閱者與重放者，關閉期間不漏資料。 SW 隨時會被回收，跨事件狀態一律落地。
核心零瀏覽器依賴 utils/state.ts、utils/battle.ts 等核心不碰 chrome.*／DOM， 能用 samples/ 在 Node／Vitest 驗證。
權限精簡 正式 build 的 host_permissions 為空；DMM 頁的存取走 optional_host_permissions， 只在使用者操作時請求。

03技術棧與專案佈局

WXT ＋ TypeScript，執行期唯一依賴是 Dexie（IndexedDB）。沒有 UI 框架、CSS 框架或圖表庫： 畫面是手寫 HTML 字串加事件委派，樣式內聯於各 index.html，折線圖是自算幾何加手寫 SVG。 依賴版本與指令以 package.json 為準。

├─ entrypoints/

MV3 開發流程限制

改完 source 後須 rebuild、在 chrome://extensions 重新整理擴充， 已開著的遊戲分頁還要 F5 才會重新注入 content script。

為什麼是兩支 content script

只有 MAIN world 碰得到遊戲的 window.axios，但 MAIN world 沒有 browser.* API。 因此拆成「MAIN 觀察 → 私有 MessagePort → ISOLATED 轉 runtime message」兩段；只有 document_start 的握手經過 window，之後的封包不在頁面上廣播。遊戲靜音的 hook 也必須在 MAIN world 的 document_start 安裝，早於遊戲建立音訊圖。

05資料生命週期

  1. 擷取：interceptor 觀察回應 → idle queue 依序送出 → bridge 去憑證、建立固定 captureId 的 envelope（retry 最多一次且沿用同一 envelope）。
  2. Ingestion：background 解析後只經 ingestEvent() 寫 db.events。 新事件先存 pending，claim 後 processing，副作用成功才 done； SW 啟動時回收遺留的 processing，recovery 與新事件共用同一條順序 queue。
  3. Post-processing（background）：廣播 kc:live、寫 snapshot、資源序列、任務觀測、 排程通知、裁剪。
  4. 投影（面板）：EventProjector 依 projection cursor 把 raw events 寫成出擊、 工廠、重播、遠征等 derived tables；cursor 前的事件只重建狀態。每筆成功才推進 cursor。
  5. 裁剪：raw event 只有在已投影且不受保護時才刪；metadata 無效就停止裁剪。
  6. 狀態復原：面板與情報總括都以「安全 snapshot baseline ＋ 重播保留中的 raw events」建 GameState；snapshot 只當 baseline，絕不送進 projector。情報總括只讀，不投影。

各步驟的契約與理由見 docs/engineering/capture.md；匯入（單場 JSON、CSV）借用 event ID 但不寫 raw event 的例外路徑見 docs/engineering/records.md。

06重建順序

只有在原始碼無法還原（§1 的備份也遺失）時才需要從頭重建。建議順序：

  1. WXT 專案骨架、wxt.config.ts 的 manifest 與 build hook、三語 public/_locales； 先讓權限契約（host_permissions 為空）成立。
  2. utils/db.ts 的 schema 與 row interface。
  3. 擷取管線：utils/kcsapi.ts、utils/axios-capture.ts、utils/idle-capture-queue.ts、 utils/main-channel.ts，以及兩支 content script。完成後應能在 SW console 看到 kc:api 訊息。
  4. utils/ingestion-persistence.ts、utils/background-ingestion-lifecycle.ts， 再接上 background.ts 的 ingestEvent()。
  5. utils/state.ts 的 GameState：先做 master／port／艦隊，用 samples/ 驗證。
  6. utils/battle.ts：用真實戰鬥封包對照 rank、MVP、終末 HP。
  7. utils/event-projector.ts、utils/projection-cursor.ts、utils/state-recovery.ts。
  8. 面板。到這裡是最小可用系統。
  9. utils/event-pruning.ts 與其餘 post-processing 副作用。
  10. popup、情報總括的殼與各分區。
  11. 備份、還原與重播保留。這一步最容易造成資料損失，先寫測試。

07最容易做錯的事

紅線
  1. 把擷取寫成主動請求，或包住原生 fetch／XHR：違反被動觀察，也會讓其他擴充的 DevTools 讀不到封包內容。
  2. 繞過 ingestEvent() 直接寫 db.events：去重、狀態機與 recovery 全部失效。
  3. 把 db.snapshot 送進 EventProjector：snapshot 只是 baseline，投影會產生重複的 derived rows。
  4. 猜測未驗證的封包欄位：沒有真實樣本或成熟工具的解析程式碼佐證時，保留原始值或回 null，介面顯示「不可考」。
  5. 備份還原寫成 merge：還原只接受乾淨環境的完整 transaction，任一步失敗整個 rollback。
